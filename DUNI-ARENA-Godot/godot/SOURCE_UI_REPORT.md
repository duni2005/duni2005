이번 요청은 이전의 푸른색 선호를 변경하여 **HTML 원본의 색감도 따르는 것**이다. 원본 `style.css`, `tower.js`, 실제 HTML 실행 화면 및 첨부 8580/8577/8574를 기준으로 수정했다. 새로운 밸런스·AI·경제 규칙은 만들지 않았다.

## 일시정지

원본 전투 하단의 실제 일시정지를 연결했다. 일반 전투의 frame 경계에서 BattleManager와 표현의 기존 processing 상태를 보관하고 정지/복원한다. `BattleClock`, `Engine.time_scale`, TP/초월 규칙, RNG 값은 수정하지 않는다. TP·초월·전투 종료 중에는 시작할 수 없으며, 후퇴와 정산 시 정지 상태가 종료 연출을 막지 않도록 해제한다. 저장 대상이 아닌 관전 UI 상태다. 테스트에서는 원래 processing=false인 경우와 실제 true인 경우 모두 복원/시간·RNG 동결을 확인한다.

## 실제 캡처와 검사

`migration/source-ui/html/`의 캡처는 수정하지 않은 HTML을 직접 실행한 화면이다. 결과 화면은 원본 renderer에 명시적인 결과 fixture를 공급한 시각 비교이며, 정산 정확성을 검증하는 수단은 아니다. Godot 결과 화면은 실제 기존 전투 정산을 거친 fixture다. 모바일 390×844와 PC 1280×800의 수정 후 화면, 직전 버전 화면을 보관했다. 비교 페이지 `/ui-review/`에서 확인할 수 있다. 전투 시점·적/재화는 각 실행마다 달라 픽셀 또는 RNG 일치를 주장하지 않는다.

- 전체 기존 회귀: **120,324 검사 / 실패 0**.
- 최종 VFX ON/OFF paired/12vs12/정리 재검사: **22,865 검사 / 실패 0**.
- 신규 원형 도구/보상 모달/결과/전투 관전 검사: `source_ui_runner.gd`, X11 실행 로그.
- 기존 터치, 모바일 비율, 콘텐츠, 이벤트, TP/종료 연출 및 유닛 멈춤 검사 유지. 이전 ‘파란색’ 기대값은 이번 요청에 따라 실제 원본 색으로 변경했다. 네 도구 검사는 안내 Label을 버튼으로 세지 않도록 Button 네 개를 검사한다.
- 최종 모바일 브라우저의 입력/복귀 결과는 `browser-release.log`, `source-dpr3-browser-results.json`에 기록한다. DPR 3 입력과 CSS 390×844를 사용하며 VM 소프트웨어 렌더러의 전투 대기는 DPR 1이다. 물리 기기 FPS 검증으로 주장하지 않는다.

## 파일과 보존 경계

새 표현 클래스: `DeploymentToolButton`, `ConquestRewardButton`, `ConquestRewardPanel`. 새 아이콘: `energy.svg`. 변경 파일은 화면, 표현 renderer, UI SVG와 테스트다. AI·전투 rule·DamageResolver·BattleClock·TowerController·save serializer·Resource 스탯은 변경하지 않았다. 웹 원본 19개와 보호 대상의 SHA-256은 `before-hashes.json`, `after-hashes.json`, `hash-verification.json`에 기록한다. 사운드 작업은 없다.

## 남은 차이 / MIGRATION_NOTE

원본과 모든 animation frame이 동일한 것은 아니다. HTML DOM과 Godot Control의 글꼴 측정·배치 및 화면 전환 방식 차이는 남는다. 고유 공격/VFX는 기존 표현 시스템을 유지하며, 원본의 타입 아이콘과 UI 색·배치를 이번에 더 가깝게 맞췄다. 비교 자료에는 없는 변경 전 캡처를 만들어 넣지 않았다.

저장 schema v1, 안전 checkpoint, 안정 ID와 receipt는 유지한다. 새 관전 정지/처치 카드/도구 선택 안내는 저장되지 않는다. 보상/결과 UI는 기존 정산 데이터를 읽으며 다시 지급하지 않는다.

이번 수정만 되돌릴 기준 Site commit은 `362175258744e1b46d3c1f98546c4d2ff08422f6`이다. 해당 게임/정적 산출물을 복원·재배포하거나 `migration/source-ui/before/`의 대응 스크립트를 복원하고 추가 표현 클래스/아이콘을 제거한 뒤 다시 Web export한다. HTML 원본이나 이전 Phase 도메인을 초기화할 필요가 없다.
