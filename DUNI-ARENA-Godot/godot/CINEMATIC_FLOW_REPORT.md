# 전투 종료·터닝포인트 연출 정리

요청한 순서에 맞춰 승리·패배·전체 후퇴를 하나의 종료 연출로 묶었다. 결과 텍스트와 결과 페이지가 즉시 나타나지 않는다. 화면 하단 사망 로그와 선택 유닛의 원시 상세 정보는 기본적으로 숨겼다. F3 개발 검사는 유지한다.

## 화면 흐름

| 종료 이후 실제 시간 | 표현 |
|---|---|
| 0–1.25초 | 현재 관전 확대에서 전체 전장이 보이는 배율로 부드럽게 축소 |
| 0–0.6초 | 종료 직전 포즈·이동 방향을 복사한 시각 요소가 느리게 이어짐 |
| 0.6–1.85초 | 복사된 유닛·투사체 표현이 점차 감속하여 정지 |
| 1.85초 이후 | 전장 주변과 배경이 서서히 어두워짐 |
| 2.4초 이후 | 제목·문양·빛 선·유한 입자가 페이드/작은 스케일 변화로 등장 |
| 3.6초 | 승리·패배 결과 페이지 표시 / 전체 후퇴는 지도 복귀 |

승리는 금색 왕관/잎 장식, 패배는 적색 해골, 후퇴는 코랄색 깃발과 방향성 잔광으로 구분한다. 예측 전투는 실제 선택한 팀의 결과에 따라 `예측 성공 / 예측 실패 / 무승부`를 표시한다. 제목을 둘러싼 사각 박스는 없다.

터닝포인트의 기존 **2초 감속 / 40초 전략 대기** 규칙은 유지한다. 감속 중 카메라가 전체 전장을 보여주고, 정지 후 청록색 시계판과 **시계 아이콘 + 터닝포인트** 한 줄이 나타난다. 추가 설명 문구는 없다. 재개 입력은 기존 경로를 사용한다.

## 구조와 게임 상태 보호

- `BattleCinematicState`: 종료 연출의 실제 시간, 복사된 포즈/위치/속도, 감속 적분을 관리하는 순수 데이터.
- `CinematicArtwork`: 시계판·제목·비네트·입자를 그리는 결정론적 표현 코드.
- `CombatPresentation`: 기존 `battle_finalizing` 신호에서 전투 정리 이전의 표현 값만 복사한다.
- `CharacterPainter`: 복사된 포즈를 그린다. 살아 있는 Unit을 다시 이동시키거나 공격시키지 않는다.
- `RetreatPresentation`: 기존 클래스 이름을 유지하면서 세 종료 이유가 공유하는 전체 화면 표현으로 확장했다.
- `CameraController`: 종료 연출용 1.25초 전체 전장 전환과 기존 TP용 2초 전환을 제공한다.
- `RoomBattleScreen / TowerBattleScreen`: 단일 결과 ID를 기준으로 연출 시작을 한 번만 허용하고 결과 표시를 지연한다.
- `TowerContentScreen`: 예측 전투에도 같은 종료 흐름을 적용한다.
- `WalletBar / TowerScreen`: 이미 정산된 재화의 화면 이동 효과가 종료 제목을 가리지 않도록 잠시 지연한다.

실제 전투는 기존 종료 시점에 정지하고 정산·보상·자동저장을 완료한다. 이후 화면에서 보이는 움직임은 복사본이다. 그 사이 **실제 위치·HP·RNG·전투 시계·적 지속 상태·영수증**은 바뀌지 않는다. `Engine.time_scale`, AI, BattleClock, 정산 계산은 수정하지 않았다. 결과 화면을 위해 보상이나 정산을 다시 호출하지 않는다.

일반 전투에서 노란 사망/Player HP 로그와 하단 흰색 이름·HP·게이지·능력 상세를 숨겼다. 파티 카드, HP/상태 표시, 후퇴 버튼은 유지한다. F3에서는 기존 상세 검사가 가능하다.

- 웹 export: Godot 4.6.3, `web-build.log`. 배포 PCK SHA-256: `b752fba5c1aecd434a246de2d09b07ea34b93923bc05269ac0007c76fb0c59ab`.
- 원본 웹 **19개 SHA-256 전부 일치**. AI·전투 시계·전투 관리/정산·타워 진행·저장·정적 데이터 등 보호 대상 **62개 파일 해시 일치**. 상세는 `hash-check.json`.

신규 X11 종료 시나리오는 알려진 위치·속도를 가진 자동 fixture이다. 웹 검사는 실제 이어하기→배치→전투→TP→재개→후퇴→지도 입력 경로이다. 소프트웨어 WebGL 환경에서는 대기 중 DPR 1, 입력·캡처 때 DPR 3을 사용하므로 실제 휴대전화 FPS 검증으로 간주하지 않는다.

## 남은 표현 차이

종료 뒤 이어지는 포즈는 복사된 속도와 감속을 사용하는 짧은 시각적 마무리이다. 새로운 AI 판단·유닛 충돌·피해·공격 시전을 재생하지 않는다. 게임 상태를 다시 진행시키지 않으면서 요청한 감속 순서를 표현하기 위한 경계다. 모든 웹 픽셀 애니메이션의 프레임 일치를 주장하지 않는다. 사운드 작업은 하지 않았다.

## MIGRATION_NOTE

저장 schema v1, `DUNI_ARENA` user data 경로, 안전한 전투 checkpoint 계약은 그대로다. 종료 연출 중 앱을 닫으면 이미 저장된 정산 이후 상태로 기존 라우팅을 사용한다. 연출 객체/포즈/카메라 나이는 저장하지 않는다. 3.6초의 화면 지연이 새 전투 결과나 추가 보상을 만들지 않는다.

수정본은 기존 미리보기 주소 `https://duni-arena-godot-125.kanduni.chatgpt.site`에 배포했다. 소스 commit `32bc23beb96d16d6184c20778d3ec3ba64737da8`, 배포 성공 기록은 `migration/cinematic-flow/deployment.json`에 있다. 접근 범위는 기존 owner-private를 유지했다.

## 이번 변경만 되돌리기

배포 소스의 직전 버전은 `cbfa15d5482afd83ac0b7c71f54899e57030e741`이다. 로컬에서는 `migration/cinematic-flow/before/`의 변경 전 스크립트를 해당 경로로 복원하고 신규 `battle_cinematic_state.gd`, `cinematic_artwork.gd`와 각각의 UID를 제거한다. 이번에 조정한 UI 검사 타이밍도 이전 종료 연출 시간으로 되돌린 뒤 웹 export를 다시 만든다. 이전 이벤트 패리티·카운터 정지 수정은 유지한다. 기존 웹 원본을 되돌릴 필요는 없다.
