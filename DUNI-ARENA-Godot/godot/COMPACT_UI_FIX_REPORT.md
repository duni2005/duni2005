# 원본 UI 구조·크기 보정

기능 버튼을 한 화면에 모두 나열했던 구성을 HTML 원본의 메뉴·탭 구조로 다시 정리했다. 기존 CSS 논리 화면 보정은 유지하며, 전체 캔버스를 축소하는 방식은 사용하지 않는다.

## 원본 확인과 변경

원본 dist/를 실제 Chromium에서 390×844와 1280×720으로 실행하고 지도·메뉴·유닛·인벤토리·강화·모집·상점을 캡처했다. 캡처와 치수 기록은 `migration/ui-parity-fix/html/`, `html-measurements.json`에 있다.

| 화면 | 이전 문제 | 변경 |
|---|---|---|
| 지도 | 새 런·포기·관리·저장·메인 버튼 나열 | 유닛·메뉴 두 개의 원형 버튼. 나머지는 메뉴 안으로 이동 |
| 방 카드 | 휴대폰에서도 148px 폭 | 54×100px. 첫 층 6개 방이 가로 스크롤 없이 표시됨. 이후 방 수가 많은 층은 스크롤 유지 |
| 층 | 정복 버튼이 층 이름 옆 공간 차지 | 원본처럼 오른쪽에 작은 보상 버튼 |
| 길드 | 목록·강화·인벤토리를 모두 세로 적재 | 유닛목록·인벤토리·강화 탭. 기본 목록은 2열 카드 |
| 관리 창 | 별도 큰 제목줄·하단 닫기 | 내용 안에 제목·상단 닫기. 탭 전환 후 화면 내 크기로 재정렬 |
| 인벤토리 | 큰 세로 카드 목록 | 4열 아이템 슬롯, 별도 길드원 선택, 설명을 통한 장착 |
| 모집 | 175px 후보 가로 스크롤, 큰 리롤 카드 | 후보 3명을 한 줄에 표시, 작은 리롤 버튼을 위쪽 오른쪽에 배치 |
| 상점 | 장비·카드를 모두 세로 나열 | 장비 구매·전략카드·인벤토리 탭, 상품 카드 격자 |
| 배치 | 여러 편집 버튼 상시 표시 | 시작·배치 도구·정비 중심. 해제/초기화/복원은 배치 도구 안에 보존 |
| 전투 | 큰 정보·조작 패널 | 골드/토큰/플레이어 HP, 별도 작은 전투 시간/인원, 전장, 작은 파티 게이지, 후퇴 순서 |
| TP | 큰 카드/대상 패널과 상시 사용·취소 | 작은 대상/카드, 한 줄 성향, 카드 선택 시 사용·취소 표시 |
| 결과 | 고정 높이 때문에 큰 빈 공간 | 줄 수에 맞는 결과 영역. 긴 결과만 스크롤. 중앙 지도 복귀 버튼 유지 |
| 공통 | 기본 16px, 큰 여백 | 기본 14px, 작은 패딩. 메뉴 아이콘은 글꼴 의존 없이 벡터로 표시 |

## 검증

- 최신 합산 UI 검사: **14개 스위트, 23,236개 검사, 실패 0** (`verified-ui-results.json`).
- 최종 결과창 크기 조정 후 레이아웃 재검사: **100개, 실패 0** (`result-layout-final.log`).
- 최종 Phase12 UI/paired 검사: **22,692개, 실패 0**. 900 paired ticks에서 HP·위치·공격 상태·RNG 동일, effects≤85 / numbers≤35.
- 구매·장착·강화·저장/이어하기·재도전 등 기존 입력 검사 유지. 새 메뉴·탭 경로를 통해 실제 마우스/터치 입력으로 검사하도록 GUI 테스트를 갱신했다. 상점 검사는 장비/전략카드 탭을 각각 확인한다.
- X11에서 PC/모바일 화면 캡처 및 22개 화면 구조 검사 통과. Chromium에서 390×844, DPR3 입력으로 지도·메뉴·길드 탭·모집 구매·지도 복귀·상점 확인 (`browser-ui-results.json`).
- 동일 웹 패키지의 전투→TP→재개→후퇴→중앙 결과→지도 복귀 흐름 통과 (`compact-dpr3-browser-results.json`). 소프트웨어 WebGL의 시뮬레이션 대기는 DPR1, 입력/증거 캡처는 DPR3를 사용했다. 실기기 FPS 검사는 아니다. 이 브라우저 흐름 이후 결과의 고정 빈 공간만 추가로 줄였으며, 해당 변경은 위 100개 레이아웃 검사로 재확인했다.
- 전체 master의 Phase1~11은 실패 0. 초기 실행에 남았던 2개 기존 UI 구조 검사는 새 탭 경로/상품 격자에 맞춰 갱신하고 Phase12 스위트를 다시 통과했다. 초기 실패/중간 실행 로그도 보존한다.
- 원본 웹 **19개**, 보호된 전투/도메인 **173개**, AI **9개**, save **8개** SHA-256 변경 없음. 저장 schema v1·기존 저장·게임 규칙 유지. 사운드 작업 없음.

## 파일과 근거

수정한 게임 파일은 `scripts/`의 main_menu_screen, tower_screen, tower_content_screen, guild_management_panel, deployment_screen, room_battle_screen, tower_battle_screen, turning_point_panel 및 `presentation/`의 ui_style, arena_card, wallet_bar다. 신규 `tests/ui_parity_smoke.gd`와 기존 GUI 테스트의 이동/탭 경로를 추가/수정했다. 배포용 browser harness는 `firebase/validate_compact_battle.py`다.

`migration/ui-parity-fix/tower-comparison.png`, `guild-comparison.png`에서 HTML / Godot 이전 / 수정 후를 비교할 수 있다. 캐릭터 그림·글꼴·일부 장식은 HTML과 픽셀 단위로 일치하지 않는다. 이번 수정의 기준은 메뉴 구조, 크기, 배치, 조작 공간이다.

## Migration note / 되돌리기

메뉴로 숨긴 기능은 삭제하지 않았다. UI는 기존 도메인 API만 호출하며 정산/보상을 표시 때문에 재실행하지 않는다. 반응형 기준은 CSS 논리 크기를 유지한다. UI를 되돌리려면 `migration/ui-parity-fix/before/`의 11개 스크립트를 복원하고 해당 메뉴/탭 GUI 테스트도 함께 되돌린 후 Web 빌드를 다시 만든다. 배포는 기존 Site의 이전 버전으로 돌릴 수 있다. 현재 배포 ID와 커밋은 `publication.json`에 기록한다.
